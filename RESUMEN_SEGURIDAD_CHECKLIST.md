# Resumen Ejecutivo de Seguridad - Ruta Zero FSM

A continuación se listan las funciones tecnológicas exactas y barreras de seguridad implementadas en cada componente de la plataforma.

## 1. Infraestructura Cloud (Render + DigitalOcean VPN)
*   **DigitalOcean Droplet (OpenVPN / WireGuard):** Sirve para crear un túnel encriptado de acceso exclusivo. Protege la conexión remota del equipo de desarrollo. *Ejemplo:* En lugar de conectarse desde la IP pública de una cafetería, los desarrolladores se conectan a la VPN y obtienen una IP estática empresarial para acceder a los servidores de producción.
*   **Render IP AllowList (Lista Blanca):** Sirve para bloquear todas las conexiones entrantes a la Base de Datos que no vengan de IPs autorizadas. Protege la base de datos de escaneos masivos en internet. *Ejemplo:* Se configura para que solo la IP del servidor API en Node.js y la IP fija de la VPN de DigitalOcean puedan acceder al puerto de PostgreSQL.
*   **Cloudflare L3/L4 DDoS Protection:** Sirve para absorber picos masivos de tráfico falso. Protege la disponibilidad del servidor de caídas inducidas. *Ejemplo:* Si una botnet intenta mandar 100,000 peticiones por segundo a la API, Cloudflare las mitiga antes de que siquiera toquen el servidor en Render.
*   **Render Managed TLS 1.3:** Sirve para encriptar los paquetes de datos mientras viajan por la red. Protege contra la interceptación de información (*Man-in-the-Middle*). *Ejemplo:* Cuando la App envía contraseñas o montos financieros, viajan en un sobre cifrado irrompible.

## 2. API REST (Backend en Node.js)
*   **express-rate-limit:** Sirve para evitar el ataque de fuerza bruta limitando la cantidad de peticiones permitidas por IP. Protege las cuentas de usuario de ser hackeadas por bots que prueban millones de contraseñas. *Ejemplo:* Se restringe el endpoint `/api/auth/login` a un máximo de 5 intentos fallidos; si el usuario se equivoca 6 veces, el servidor le bloquea la IP temporalmente por 15 minutos.
*   **jsonwebtoken (JWT):** Sirve para autorizar transacciones de forma segura firmando la identidad del usuario (algoritmo HS256). Protege contra la suplantación de identidad. *Ejemplo:* Se genera un token con un tiempo de vida de apenas 15 minutos; si un atacante logra copiar el token de una red pública, el servidor lo rechazará rápidamente por caducidad.
*   **helmet.js:** Sirve para configurar automáticamente encabezados de seguridad HTTP restrictivos. Protege contra ataques XSS y *Clickjacking*. *Ejemplo:* Oculta el encabezado `X-Powered-By` para que un hacker no sepa que se usa Express, y envía directivas CSP que bloquean a cualquier otra web de incrustar el portal Ruta Zero dentro de un `iframe` falso.
*   **cors:** Sirve para rechazar peticiones que provienen desde orígenes web no reconocidos. Protege contra ataques CSRF. *Ejemplo:* La API está configurada para abortar inmediatamente cualquier conexión HTTP (Ajax/Fetch) que no se origine explícitamente desde el dominio oficial `https://portal.rutazero.com`.
*   **express-validator (Sanitización):** Sirve para limpiar y validar todos los datos de entrada antes de procesarlos. Protege la base de datos de envío de código malicioso. *Ejemplo:* El uso de la función `.escape()` convierte caracteres peligrosos como `<script>` en texto inofensivo si alguien intenta inyectarlos en el campo de "Nombres" o "Observación".
*   **Middlewares (authMiddleware, adminOnly):** Sirve para ejecutar el Control de Acceso Basado en Roles (RBAC). Protege la privacidad de los módulos administrativos. *Ejemplo:* Si un `WORKER` intenta mandar un POST oculto al endpoint `/api/amonestaciones`, la función `adminOnly` lee el token, verifica que su rol no es `ADMIN` y devuelve un error `403 Forbidden` deteniendo el proceso.

## 3. Base de Datos (PostgreSQL)
*   **node-postgres (pg) Queries Parametrizadas:** Sirve para separar lógicamente los comandos SQL de los datos ingresados por el usuario. Protege al 100% contra el ataque de inyección SQL (*SQL Injection*). *Ejemplo:* En el código, en lugar de concatenar cadenas (`WHERE username = '` + input + `'`), se usa `WHERE username = $1`. Si el atacante ingresa `' OR 1=1 --`, la base de datos lo lee estrictamente como un texto y no lo ejecuta como comando.
*   **bcrypt:** Sirve para ofuscar contraseñas de forma irreversible aplicando algoritmos de costo (Salt rounds). Protege los accesos en el escenario catastrófico de una filtración de base de datos. *Ejemplo:* La clave "Peru2026" se guarda como el hash `$2b$12$R9hK...`, lo cual hace matemática y computacionalmente imposible revertirla para saber cuál era la clave original.
*   **Point-in-Time Recovery (Backups de Render):** Sirve para guardar estados históricos del disco duro. Protege contra la pérdida accidental o manipulación maliciosa de registros. *Ejemplo:* Si un supervisor borra equivocadamente toda la tabla de "Clientes" a las 14:00, el sistema permite restaurar la base de datos con los datos exactos que tenía a las 13:59.

## 4. Portal Web (Administración React SPA)
*   **React Router Dom (Protected Routes):** Sirve para bloquear la navegación web por interfaz. Protege el acceso visual a vistas sensibles. *Ejemplo:* Si una persona copia la URL directa `/ciclos` en modo incógnito, el componente validará que no existe una sesión y lo expulsará inmediatamente redirigiéndolo a `/login`.
*   **Almacenamiento de Sesión en Memoria (RAM):** Sirve para almacenar la credencial temporal de forma volátil. Protege contra robos de sesión (*Token Theft* vía XSS persistente). *Ejemplo:* Al no guardar el token en el `localStorage` o `Cookies`, cualquier código malicioso no puede encontrarlo en el disco. Además, si el usuario cierra el navegador, la sesión se evapora físicamente del computador.
*   **Aislamiento Lógico por Multitenancy (Filtro por Sede_ID):** Sirve para segregar la visualización de la cartera. Protege el negocio limitando el alcance de datos por sucursal. *Ejemplo:* En cada petición que hace la tabla del dashboard, se adjunta la variable de la sede del usuario logueado. Un administrador de Arequipa tiene bloqueado a nivel de frontend y backend ver las métricas de Lima.

## 5. App Móvil (Asesor de Campo - React Native)
*   **Expo SecureStore:** Sirve para guardar el token de autenticación encriptado a nivel de hardware. Protege las credenciales si el celular físico es robado o comprometido por virus. *Ejemplo:* En iOS, se usa el *Secure Enclave*; en Android, el *Keystore*. Los datos allí son ilegibles para otras aplicaciones del teléfono.
*   **Validación de "Estado Activo" en Tiempo Real:** Sirve para invalidar el acceso de dispositivos remotos al instante. Protege la información ante el despido o cese de un empleado. *Ejemplo:* Si el administrador inactiva a un asesor en el portal, la próxima vez que el celular de ese empleado intente pedir una ruta a la API, el servidor arrojará un error 403, y la app purgará la sesión y borrará todos los datos en pantalla regresando al Login.
*   **Inyección de Metadata y Bloqueo de Galería:** Sirve para estampar marcas de auditoría imposibles de borrar directamente en el archivo JPG de la cámara. Protege contra falsificaciones fotográficas (fraude). *Ejemplo:* La app bloquea la opción de "Subir desde Galería". Obliga a tomar una foto en vivo e incrusta las coordenadas GPS exactas y el Timestamp del servidor en los píxeles de la imagen, impidiendo que el asesor use una foto guardada de días anteriores.
